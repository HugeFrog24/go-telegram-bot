# Parsing untrusted video safely: pitfalls, CVEs and prior art

Research for the video-watching feature (Task 0 of `docs/superpowers/plans/2026-11-16-video-watching.md`). It decides the hardening that Task 2 (ffmpeg layer) and Task 8 (Docker/CI) implement. The controller rules on each recommendation in §6.

- **Date:** 2026-11-16. Every source in §8 was accessed on 2026-11-16.
- **Citations:** `[S#]` is a web source. `[L#]` is a local check, run on 2026-11-16 against ffmpeg/ffprobe 9.0.2 (gyan.dev "essentials" build, Windows) with synthetic clips generated by `ffmpeg -f lavfi`.
- **Safety:** no untrusted sample or exploit code was run. The one playlist test (L3) used an ordinary HLS playlist that ffmpeg's own HLS muxer wrote next to its own segment.

**In scope:**
- **Containers:** MP4/MOV, Matroska/WebM, GIF and Telegram round videos.
- **Codecs:** H.264, HEVC, VP8/VP9 (with alpha), AV1 and GIF.
- **ffmpeg:** 9.x locally, and Alpine's `ffmpeg` package in the Docker image.
- **Go side:** shelling out with `os/exec`.

**Method:**
- **CVEs:** NVD's JSON API (`keywordSearch=ffmpeg`, `libvpx`, `dav1d`), FFmpeg's security page, GitHub's advisory database, Alpine's package index and APKBUILD `secfixes`.
- **Web searches:** standard and extended mode.
- **Prior art:** each project's source, read from raw.githubusercontent.com, git.asonix.dog and the GitHub REST tree API.
- **Local checks:** `ffmpeg -h full`, plus small command-line checks of each flag.
- **GitHub code search was unavailable.** `api.github.com/search/code` answered `401 Requires authentication` [S47], and `gh` is not authenticated. Prior art was therefore found through web search and read file by file. Some code that would show up in a code search is missing here (see §7).

## 1. Findings in brief

1. **`-protocol_whitelist file` does not stop a crafted file from reading other local files.**
   - It does block network fetches and the `concat:`/`subfile:` pseudo-protocols.
   - But the HLS, DASH, IMF and concat **demuxers** open local files through the allowed `file` protocol. On 9.0.2, an HLS playlist probed with only `-protocol_whitelist file` was accepted (`format_name=hls`), and ffprobe opened the segment it names [L3].
   - Rails Active Storage shipped exactly this local-file disclosure on 2026-11-12 (CVE-2026-126188). It fixed it with `-format_whitelist` [S12, S14]. Telegram-bot projects found the same gap [S33].
   - So the design's line "`-protocol_whitelist file` so a crafted file cannot make it read URLs **or other files**" is wrong for "other files".
2. **The planned format allowlist is applied too late.** Checking ffprobe's `format_name` afterwards runs only after content probing has picked a demuxer and that demuxer has parsed the file. By then:
   - HLS has already opened what it references;
   - the parsing code of all ~370 demuxers in the build [L2] has been reachable, including VobSub's heap overflow (CVE-2026-64830).
   - `-format_whitelist` is checked right after probing and **before** the demuxer's `read_header` runs (`libavformat/demux.c` lines 286–290 in n9.0.2) [S39].
   - So it must be passed to **every** ffprobe and ffmpeg call, before `-i`. The `format_name` check stays as a second line.
3. **Most memory-corruption CVEs sit in codecs a 20 MB Telegram video never needs.** They can still reach the process inside an allowed container:
   - **Examples:** MagicYUV (CVE-2026-8461), CineForm (CVE-2026-70632), JPEG 2000 (CVE-2025-9951) and VVC (CVE-2026-125244) inside MOV/MKV.
   - **Fix:** an explicit decoder allowlist (`-codec_whitelist`). It cuts the 544 decoders in the local build [L2] to about 8.
   - **Pitfall found locally:** ffprobe exits 1 if **any** stream's decoder is off the list. The probe call needs a longer list (with common audio decoders) than the render call [L5, L6; `ffprobe.c` lines 2659–2662, S39].
4. **ffprobe has no `-nostdin`.** `ffprobe -nostdin` fails with "Option not found" [L9]. The global constraint "every ffmpeg/ffprobe call uses `-nostdin`" must say `-nostdin` for ffmpeg only. For ffprobe, `cmd.Stdin` stays nil (the null device) [S37].
5. **Input options must come before `-i`.**
   - `-protocol_whitelist file` placed after `-i` becomes an output option. It then blocks the `pipe:1` output [L8].
   - elttam reported the same "applies to the next file" trap in Home Assistant [S15].
6. **The 20 MB download cap does not bound decoding cost.**
   - **Threads:** the ffmpeg CLI sets decoder `threads=auto` (`fftools/ffmpeg_dec.c` lines 1571–1572) [S39], so memory scales with cores.
   - **Pixels:** `max_pixels` defaults to INT_MAX [L1].
   - **Fix:** add a pixel cap (`-max_pixels`), a thread cap and output bounds to the planned timeouts.
7. **ffmpeg runs as the bot's own user, so a decoder RCE gets the bot's secrets.**
   - That covers the config tokens in `/app/config` and any `ANTHROPIC_API_KEY` in the inherited environment: `os/exec` passes the parent environment when `Cmd.Env` is nil [S37].
   - elttam exfiltrated `/proc/self/environ` through ffmpeg this way [S15].
   - The cheap mitigation now is a minimal child environment. Real isolation (Landlock, a separate container) is "later".
8. **No ffmpeg CVE from 2022 to 2026 is flagged as exploited in the wild** in NVD's CISA-KEV field. The one KEV entry in reach is libvpx's **VP8 encoder** (CVE-2023-5217), which the bot never uses [S2, S3].
9. **Alpine ships a recent ffmpeg, but only for a while.**
   - **Versions:** v3.24 (current) ships **8.1.3**, edge ships **9.0.2-r3**, v3.23 ships 8.0.1 and v3.22 ships 6.1.2 [S6, S8].
   - **Support window:** ffmpeg lives in `community`, which is supported only "until next stable release" [S9]. A pinned branch stops getting ffmpeg fixes about six months in.
   - **Minimum version:** require **ffmpeg ≥ 8.1.3** at build time. v3.23's 8.0.1 lacks the fix for the MOV CENC overflow (CVE-2026-40962, CVSS 9.8, fixed in 8.1) [S2].
10. **133 CVEs published in October–November 2026 are still open in 9.0.2,** the latest release [S2, S11]. None that touch the allowlisted path is memory corruption on a path this bot runs. The ones that are reachable are DoS-class: a MOV `pssh` recursion, an HEVC PPS CPU loop, an HEVC film-grain divide-by-zero, a VP9 leak and a Vorbis-parser CPU loop (§2.3). Timeouts and one process per call contain them.

### 2.4 Exploitation in the wild

- **NVD's CISA-KEV field.** None of the 327 ffmpeg-keyword CVEs published since 2022-01-01 has `cisaExploitAdd` set. Among the libvpx and dav1d records, only CVE-2023-5217 (libvpx VP8 **encoding**, Chrome) does [S2, S3, S4]. This check used NVD's KEV field, not the KEV catalog itself.
- **Analogues outside ffmpeg:**
  - The H.264 research behind H26Forge (USENIX Security 2023) found decoder memory corruption in iOS, Firefox, VLC and Android, acknowledged by vendors "including Apple, Mozilla, and FFmpeg". Its Black Hat slides cite CVE-2022-22675 (AppleAVD) as exploited in the wild [S35].
  - ESET's EvilVideo (2024) was a Telegram-for-Android zero-day for sale. A payload sent through the Telegram API "appears as a 30-second video" [S20].
- **What this means for the bot:** a "video" message is attacker-chosen bytes.
  - The uploader declares `mime_type` and the video attributes (`inputMediaUploadedDocument`) [S21].
  - Whether Telegram's servers re-encode or validate the original file is not documented on that page (unverified).

## 3. Step 2: Attack techniques against ffmpeg-as-a-service

The columns say whether each control **stops** the technique:
- **P:** `-protocol_whitelist file`.
- **F (pre):** `-format_whitelist mov,matroska,gif` on every call, before parsing.
- **F (post):** the planned ffprobe `format_name` check alone.
- **C:** `-codec_whitelist`.

**Answers to the brief's questions:**
- `-protocol_whitelist file` alone stops only T1 and T3.
- A format allowlist stops T1–T7 and T9 **only if it is pre-parse** (`-format_whitelist`). A post-hoc `format_name` check stops none of them before the dangerous code has run, though it does stop their output from being used.
- Neither stops T8 (defaults do), T10, T11 or T12. T12 needs the codec allowlist.

## 5. Pitfalls on the Go side (`os/exec`)

- **Environment.** "If Env is nil, the new process uses the current process's environment" [S37]. Set an explicit minimal `cmd.Env`.
- **Cancellation.** `CommandContext` kills the process when the context ends. `WaitDelay` "bounds the time spent waiting on two sources of unexpected delay in Wait" [S37]. Set it, so a stuck pipe cannot hang `Wait`.
- **Working directory.** An empty `Dir` runs the command in the bot's working directory [S37], which is `/app`, next to `config/`. Pass absolute `file:` paths and set `Dir` to the video's own directory.
- **Binary lookup.** `LookPath` refuses programs resolved relative to the current directory (`ErrDot`, Go 1.19+) [S37]. Resolve ffmpeg once at boot.
- **No rlimits.** `syscall.SysProcAttr` on Linux has no resource-limit field. It has Chroot, Credential, Ptrace, Setsid, Setpgid, Setctty, Noctty, Ctty, Foreground, Pgid, Pdeathsig, Cloneflags, Unshareflags, UidMappings, GidMappings, GidMappingsEnableSetgroups, AmbientCaps, UseCgroupFD, CgroupFD and PidFD [S38]. Per-child memory caps need a re-exec helper, `prlimit`, or a cgroup (later).
- **Bounded output.** Read stdout through `io.LimitReader`, and keep only a tail of stderr. With `-loglevel error`, a crafted file can still produce many lines.

### Resulting argument vectors (for Task 2's tests)

```text
ffprobe -hide_banner -loglevel error
        -protocol_whitelist file -format_whitelist mov,matroska,gif
        -codec_whitelist <probe list from #2> -max_pixels 16777216
        -show_entries <Task 2's choice> -of json
        file:<absolute path>                         # no -nostdin; Stdin nil

ffmpeg  -hide_banner -nostdin -loglevel error
        -protocol_whitelist file -format_whitelist mov,matroska,gif
        -codec_whitelist h264,hevc,vp8,vp9,libvpx,libvpx-vp9,libdav1d,libaom-av1,gif
```

- HEVC;
- AV1, decoded by libaom;
- VP8;
- VP9 with alpha, through `-c:v libvpx-vp9`;
- GIF.
